Data pack для дипломної роботи: інтерактивна візуалізація Graph Edit Distance.

Тобі **НЕ потрібно** розгортати систему NaturalAGI, ти працюєш тільки з цими даними.

## Що таке GED

**Graph Edit Distance** — спосіб виміряти, наскільки два графи схожі:

1. Беремо два графи (граф зображення і граф концепту)
2. Знаходимо мінімальну послідовність операцій, щоб перетворити один граф в інший
3. Кожна операція має вартість (cost)
4. Чим менша сумарна вартість — тим більше графи схожі

**Три типи операцій над вузлами:**

| Тип | Що означає | Cost |
|-----|-----------|------|
| **substitution** | Вузол з image зматчився з вузлом з concept | Залежить від різниці properties (0.0 – 1.0) |
| **deletion** | Вузол є в image, але нема пари в concept | 0.25 (фіксована) |
| **insertion** | Вузол є в concept, але нема пари в image | 100.0 (дуже дорого — зображення не покриває концепт) |

**Формула нормалізації** (Boria et al. 2019):

```
similarity = 1 - cost / (cost + max(n1, n2))
```

де `n1`, `n2` — кількість (вузлів + ребер) кожного графа. Результат від 0 до 1, де 1 = ідентичні графи.

## Типи вузлів

Кожен граф складається з вузлів і ребер. Вузли бувають трьох типів:

| Тип | Опис | Колір (рекомендація) |
|-----|------|---------------------|
| **Point** | Точка скелету (endpoint, intersection, corner) | Синій |
| **Vector** | Вектор між двома точками | Зелений |
| **StartPoint** | Стартова точка обходу | Червоний |

Тип вузла визначається полем `labels` (масив рядків).

---

## Properties вузлів

Головні properties, які використовуються для розрахунку вартості substitution:

| Property | Тип вузла | Опис |
|----------|----------|------|
| `normalized_x` | Point, Vector | Координата X (від -1 до 1). **Позиція на зображенні** |
| `normalized_y` | Point, Vector | Координата Y (від -1 до 1). **Позиція на зображенні** |
| `horizontal_direction` | Vector | Горизонтальний напрямок (1=LEFT, 2=RIGHT, 3=NONE) |
| `vertical_direction` | Vector | Вертикальний напрямок (1=TOP, 2=BOTTOM, 3=NONE) |
| `cycle_count` | Point, Vector | Кількість циклів у графі |
| `angle_with_ox` | Vector | Кут вектора з віссю OX (0–180) |

**Важливо**: якщо розмістити вузли за `normalized_x` та `normalized_y` — граф буде виглядати як контур цифри.

**Різниця між концептами і зображеннями**: у концептів properties зберігаються як **діапазони** (`{"min": 0.1, "max": 0.5, "center": 0.3}`), бо концепт — це узагальнення кількох зображень. У зображень — звичайні числа.

## Формат файлів

### `concepts.json` — індекс концептів

```json
[
  {
    "concept_id": "0_1",
    "digit_class": 0,
    "complexity": 20,
    "node_count": 10,
    "edge_count": 10
  }
]
```

### `concepts/{concept_id}.json` — граф концепту

```json
{
  "concept_id": "0_1",
  "nodes": [
    {
      "id": "4:xxx:432",
      "labels": ["Point", "StartPoint"],
      "normalized_x": {"min": 0.1, "max": 0.3, "center": 0.2},
      "normalized_y": {"min": -0.5, "max": -0.3, "center": -0.4},
      "cycle_count": {"min": 0.0, "max": 0.0, "center": 0.0}
    }
  ],
  "edges": [
    {"source": "4:xxx:432", "target": "4:xxx:435"}
  ]
}
```

Для відображення вузла з діапазоном використовуй `center` як координату.

### `images.json` — індекс зображень

```json
[
  {
    "image_id": "5823b863-...",
    "digit_class": 0,
    "image_path": "images/5823b863-....png",
    "complexity": 24,
    "node_count": 12,
    "edge_count": 12,
    "predicted_class": 0,
    "best_similarity": 0.8345,
    "correct": true
  }
]
```

`correct` — чи правильно система класифікувала зображення. У data pack є як правильні, так і помилкові класифікації.

### `images/{image_id}.json` — граф зображення

```json
{
  "image_id": "5823b863-...",
  "nodes": [
    {
      "id": "abc-123",
      "labels": ["Point", "EndPoint"],
      "normalized_x": 0.2,
      "normalized_y": -0.4,
      "cycle_count": 1
    }
  ],
  "edges": [
    {"source": "abc-123", "target": "def-456"}
  ]
}
```

### `ged_results/{image_id}/{concept_id}.json` — результат GED

```json
{
  "image_id": "5823b863-...",
  "concept_id": "0_1",
  "skipped": false,
  "similarity": 0.8345,
  "raw_cost": 4.76,
  "n1": 24,
  "n2": 20,
  "node_operations": [
    {
      "type": "substitution",
      "image_node": "abc-123",
      "concept_node": "4:xxx:432",
      "cost": 0.186,
      "property_costs": {
        "normalized_x": 0.067,
        "normalized_y": 0.0,
        "cycle_count": 0.0
      }
    },
    {
      "type": "deletion",
      "image_node": "def-456",
      "concept_node": null,
      "cost": 0.25
    },
    {
      "type": "insertion",
      "image_node": null,
      "concept_node": "4:xxx:440",
      "cost": 100.0
    }
  ],
  "edge_operations": [
    {
      "type": "substitution",
      "image_edge": ["abc-123", "vec-1"],
      "concept_edge": ["4:xxx:432", "4:xxx:435"],
      "cost": 0.0
    }
  ],
  "cost_matrix": {
    "concept_node_ids": ["4:xxx:432", "4:xxx:435", "..."],
    "image_node_ids": ["abc-123", "def-456", "..."],
    "matrix": [[0.12, 0.85, 100.0], ["..."]]
  }
}
```

**Поля:**

- `skipped` — якщо `true`, порівняння не виконувалось (наприклад, концепт складніший за зображення). Поле `reason` пояснює чому. **Для візуалізації потрібні тільки файли з `"skipped": false`**
- `similarity` — нормалізована схожість (0–1), де 1 = ідентичні
- `raw_cost` — сума вартості всіх операцій
- `n1`, `n2` — кількість (вузлів + ребер) image та concept графів
- `node_operations` — список операцій над вузлами, кожна з типом, посиланнями на вузли, та вартістю
- `property_costs` — розбивка вартості substitution по кожній property (є тільки у substitution)
- `edge_operations` — аналогічний список для ребер
- `cost_matrix` — матриця вартості (рядки = concept nodes, стовпці = image nodes). Значення 100.0 = пара несумісна (різні типи вузлів)

## Задача

Створити додаток, який візуалізує процес класифікації зображень:

1. **Перегляд зображень** — список зображень з data pack, їхні графи, результати класифікації (правильно/помилково)
2. **Порівняння з концептами** — для обраного зображення показати таблицю similarity з усіма концептами
3. **Візуалізація GED** — два графи поруч (image та concept), з кольоровим кодуванням edit operations:
   - substitution — зматчені вузли (зелений)
   - deletion — вузли без пари в image (червоний)
   - insertion — вузли без пари в concept (жовтий)
4. **Cost breakdown** — розбивка вартості: по операціях, по properties, heatmap cost matrix
